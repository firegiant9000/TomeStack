# Sheet for play: features, resources, rolls and play state

SPEC C-03, C-04, C-05, I-05 · MVP "Sheet" · status: implemented (M2 item 2). Rests: [rests.md](rests.md) (M2 item 3). Rests are no longer on the Play tab: "Short rest…" and "Long rest…" are in the sheet header and their proposal opens under the summary (D29).

Rules core: `src/RulesCore/Calculation.cs` (resources, features, hit points) and `src/RulesCore/PlayState.cs`. Service: `src/AppService/Play.cs`. UI: `src/Ui/src/components/PlayPanels.tsx`. Acceptance: `tests/RulesCore.Tests/ResourceAndFeatureTests.cs`, `tests/AppService.Tests/PlayCommandTests.cs`, and the play part of the e2e test "builds an SRD 5.2.1 Barbarian as drafts".

## Features (SPEC I-05)

`sheet.features` lists every active revision (pinned, class, granted or chosen) in resolution order. Each entry has the name, kind, summary, source, page and "granted by …" / "chosen from …", the text and automation of each effect, and the problems scoped to it. Its **automation** is the least automated of its effects:

- `reference` when any effect is reference-only or unknown, or when the revision has no effects at all (for example the SRD 5.2.1 Danger Sense, which is text only). Pure text is never shown as automated.
- `assisted` when an effect needs the player (for example Stonecunning), or when a diagnostic names one of its effects (a formula that fails).
- `automatic` otherwise.

## Resources

`sheet.resources` has one entry per `resource` effect of an active revision (the first definition of a resource id in a revision):

- **Maximum:** the `maximum` formula evaluated like a modifier, in the content's own context: `CLASS_LEVEL` is the level in its class, and `PB` and fields are the displayed values. The trace step cites the content, source and page, and lists the inputs (Rage at Barbarian 3: `min(2 + floor(CLASS_LEVEL / 3), 4)` = 3, with `CLASS_LEVEL 3`).
- **A formula that fails** (does not parse, or reads `CLASS_LEVEL` outside a class) disables only that resource: no maximum, `assisted`, and an `effect.invalid-formula` warning. The rest of the sheet calculates (SPEC C-03).
- **Reference-only** resources are listed as "tracked by hand" and cannot be spent through TomeStack.
- **Current** = maximum − spent, never below 0 (a lower maximum after an update does not go negative).
- **Recoveries:** the `recovery` effects of the same revision for that resource, with the amount evaluated (`value`) unless it is `all`. They are listed only; the long rest previews them ([rests.md](rests.md)).

## Play state (character schema v4, v5)

`character.play` stores what changes at the table, separately from choices:

| Field | Meaning |
| --- | --- |
| `currentHitPoints` | Absent/null = at the maximum, so a character at full keeps full hit points after a level-up. Shown clamped to 0…maximum |
| `temporaryHitPoints` | 0 or more |
| `resources[]` | `{ contentId, resourceId, spent }`. Keyed by content id, not revision, so an update to a new revision keeps the count |
| `conditions[]` | Keys of the 14 conditions both SRDs define (`blinded` … `unconscious`). Reminders only: they do not change calculated values |
| `exhaustion` | 0–6 |
| `hitDiceSpent[]` (v5) | `{ die, spent }` per hit die size (d6–d12, 0–20). Spent on a short rest, given back by a long rest ([rests.md](rests.md)) |
| `deathSaves` (v5) | `{ successes, failures }`, 0–3 each. Three successes: Stable (the 3 stays as the marker). Three failures: dead |
| `inspiration` (v5) | Inspiration (2014) or Heroic Inspiration (2024): you have it or not |
| `toggles[]` (v7) | Active toggles (`{ contentId, toggleId }`; actions `toggleOn`, `toggleOff`; [m3-effects.md](m3-effects.md); form groups, overlays and pool costs, with the "Forms" picker on Play: [play-mechanics.md](play-mechanics.md)) |
| `spellSlotsSpent[]`, `pactSlotsSpent` (v6) | Spent spell slots per spell level and spent Pact Magic slots ([spellcasting.md](spellcasting.md); actions `spendSlot`, `regainSlot`, `spendPactSlot`, `regainPactSlot`) |
| `concentration` (v8, D19) | The concentration spell (reference and name) and a pending Constitution save DC |
| `encounter` (v10, D43 slice 3) | `{ round }`, 0 to 10,000: present only while an encounter runs. A toggle with a `duration` also carries `roundsLeft`. A character is written at v10 only while one of them is set; see [play-mechanics.md](play-mechanics.md) "Slice 3" |

**Migration on read:** character schema v1–v4 are upcast to v5 with the new state at its default (full hit points, nothing spent, no conditions, no hit dice spent, no death saves, no inspiration), which is exactly their meaning. Characters are stored as JSON and are not hashed, so no database migration is needed. A build before each version refuses its characters (`character.schema-unsupported`, `package.schema-unsupported`) instead of dropping the play state; 0.2.1 refuses v5.

## `character.play` (confirmed changes only)

`character.play { characterId, action, confirm, amount?, contentId?, resourceId?, condition?, expectedUpdatedAt? }` makes one change and returns the recalculated view. Without `confirm: true` it is refused (`play.confirmation-required`) and nothing changes. The UI sends it only from a deliberate button press.

`character.save` never changes the play state of a stored character. It keeps the stored `play`, whatever the payload carries, so a save for another reason (a name, an override, equipment), or one from a stale copy, cannot undo damage or spent uses. Only `character.play` and the confirmed `character.rest` write it. A new character keeps the play state it is first saved with (`PlayCommandTests.Saving_the_character_never_changes_its_play_state`; M2 review fix).

| `action` | Does | Refused with |
| --- | --- | --- |
| `spend` / `regain` | Spends `amount` uses (at most what is left) or regains them (at most what is spent) | `resource.not-found`, `resource.untracked`, `resource.insufficient`, `resource.nothing-spent` |
| `damage` | `amount` is the damage as rolled; an optional `damageType` (one of the thirteen, any case) applies the defences first (see "Damage types" below). Then temporary hit points absorb it; hit points stop at 0. While concentrating, sets the pending save DC to max(10, half the damage after defences, before temporary hit points), capped by the family (`RulesFamilyPolicy.ConcentrationSaveMaximumDc`: 30 under SRD 5.2.1, none under SRD 5.1) and never above 100, which validation accepts; at 0 hit points concentration ends. The reply carries `damage` (what was entered, the type, how the defences changed it, the amount after them, what temporary hit points took, what hit points lost, and warnings); it is not stored. With responses chosen, the order is D45 (see [play-mechanics.md](play-mechanics.md) "Slice 7") | `play.damage-type-unknown` |
| `heal` | Up to the maximum | |
| `setTemporaryHitPoints` | Replaces them (they do not stack) | |
| `setHitPoints` | 0 to the maximum | `play.hit-points-above-maximum` |
| `addCondition` / `removeCondition` | A known condition key | `play.condition-unknown` |
| `setExhaustion` | 0–6 | `play.exhaustion-out-of-range` |
| `recordDeathSave` | Records a death saving throw whose d20 showed `amount` (1–20), with the SRD outcome (SRD 5.1 p. 98, SRD 5.2.1 p. 17; the same in both): 10 or higher is a success, below 10 a failure, a 1 two failures, and a 20 regains 1 hit point and clears the saves | `play.not-dying` (above 0 hit points), `play.amount-out-of-range` |
| `addDeathSaveFailure` | Adds `amount` (1–3) failures, for example damage at 0 hit points (a critical hit is 2) | `play.amount-out-of-range` |
| `clearDeathSaves` | Resets both to 0 | |
| `setInspiration` | `amount` 1 gives Inspiration, 0 spends or removes it | `play.amount-out-of-range` |
| `startConcentration` | Starts concentrating on the concentration spell `contentId` from one of the character's spell lists; the spell must be prepared (a cantrip counts) and the character above 0 hit points | `play.spell-not-found`, `play.spell-not-concentration`, `play.spell-not-prepared`, `play.unconscious` |

Amounts are 0–10,000 (`play.amount-out-of-range`). **Regaining hit points clears death saving throws** (SRD): `heal` or `setHitPoints` from 0 to above 0 resets them in the same confirmed change.

## Undo (D23)

"Undo last change" on Play sends the inverse of the last play command (hit points are set back exactly; spends are regained; conditions, slots, toggles and concentration mirror). Turning on a toggle that is backed by a resource is undone by turning it off and giving the use back; turning one off cannot be undone (switching it on again would spend a use you did not spend). Concentrating on another spell replaces the first, and undoing it concentrates on the first again (a save DC that was pending on the earlier spell is not restored). A change that changed nothing (a condition the character already had) has no Undo. A change that overlapped another (quick repeated presses, which the shell runs one at a time), that was made while an Undo was running, or whose reply came after another state was shown (a rest, a snapshot restore or a save landing while it was in flight) has no Undo either, because its "before" is not the state it changed. Starting any play change withdraws the Undo on offer at once, so an Undo can never run between a change and its reply. Damage that raised a Constitution save DC also clears it, and damage to 0 that ended concentration starts it again after the hit points are set back. One level, for this sheet while it is open; nothing is stored. The button is offered only while the sheet still shows the state that change produced: a rest, a save, a level-up or a reload makes it disabled, so Undo cannot overwrite them. Death saves and ending concentration cannot be undone (no exact inverse); snapshots cover the rest. Regaining hit points from 0 clears the death saves, and no command puts them back, so while saves are recorded that change offers no Undo (rather than an Undo that silently wipes them). Damage that raised an already pending concentration DC leaves the raised DC. If a later step fails, the steps already applied are shown and the error is reported. After Undo, focus moves to the hit points heading (hit point changes) or the compact view checkbox. A companion's hit point changes are undone too ("Companions" below).

**A form switch is undone by the service (D44).** Switching from one form to another also turns the old form and its overlays off and pays a cost, which the client cannot put back. The service keeps the play state from before the switch, and while it is still the latest change the view carries an `undoLabel`: the button then reads "Undo switch to Tide form" and calls `character.undoPlay`, which restores the exact state, pool included. There is one Undo at a time: the client entry from before the switch is withdrawn. A rest, save, restore or another play change ends the offer, and a refused undo shows the service's words (`undo.stale`, `undo.nothing`, or `character.stale`, which also reloads the current copy). One level, in memory, gone when the app closes. See [play-mechanics.md](play-mechanics.md) "Slice 2". A switch sent from an out-of-date sheet is refused as `character.stale` (`character.play` takes `expectedUpdatedAt`; a form switch without it is `play.basis-required`).

**Turns and the encounter are undone the same way (D43 slice 3).** "Start encounter" and "End encounter" are compound, and so is a confirmed turn (`character.turn`); each sets the service's one undo slot, labelled "start encounter", "end encounter", "turn start" or "turn end", so the button reads "Undo turn start", "Undo end encounter" and so on. The undo puts the whole play state back (the round, the durations, the pools and the toggles the turn ended). A client entry from before is withdrawn, the button is disabled while a turn confirm is in flight, and a rest, save or other play change ends the offer, as above.

## Combat strip and turns (D43 slice 3)

The "Combat" region sits above the two Play columns. It appears when the sheet has a toggle with a form group or a `duration`, a resource that is an allowance, an upkeep, or an encounter in progress; otherwise Play looks as before. It holds:

- the **Forms** picker (moved here from "Attacks and actions"; [play-mechanics.md](play-mechanics.md));
- the **round**: "Round N" while an encounter runs (it reads "Round 1" at round 0, before the first turn), "No encounter running" otherwise, and "Start encounter" or, while one runs, "Start my turn", "End my turn" and "End encounter". The buttons are disabled while another change is in flight;
- **Timed effects**: each toggle that is on and has a duration, as "N rounds left" or "duration: track by hand" when it has no count (it was switched on outside an encounter);
- **Combat pools**: a counting-up pool as "Strain: built up 3 of 5" (and " · full: <the pool's text>" when it is full) and an allowance as "1 of 2". It is all text.

"Start my turn" and "End my turn" open the **turn panel** under the strip, in the pattern of the rest panel: a checklist of what the turn changes (each row ticked and untickable, a required ending checked and disabled with "(required)"), a radio group for each pool that cannot pay ("End <toggle>" chosen at first, "Keep it on"; one tab stop per group), "What happens" for the selection as it stands, any pool messages and the steps to do by hand. A tick or a choice fetches a new preview, and "Confirm start of turn" / "Confirm end of turn" (`aria-disabled` until it arrives) applies exactly the previewed turn, with the End choice sent explicitly even when it was never clicked. A turn that changes nothing says "Nothing changes this turn" and offers Close; if one is confirmed anyway (a preview that went empty in between), the service writes nothing and keeps the earlier Undo. A stale or refused confirm leaves the panel open and previews again. Pool messages and by-hand notices from the reply (`turn.settle-by-hand`, `turn.resource-full`, `resource.full`, `encounter.duration-by-hand`) are shown on the status line, joined with " · ".

**Amount box.** Each resource card has "Amount to spend: <pool>" and "Spend amount: <pool>" beside "Spend 1" and "Regain 1"; the button is `aria-disabled` (never `disabled`) unless the amount is a whole number from 1 to what is left (for a counting-up pool, what is left to build up), and a plain-text reason ("Enter an amount first.", "No Focus left to spend." or "Enter a whole number from 1 to 5.") is linked to the box and the button with `aria-describedby`. A counting-up pool's heading reads "Strain: built up 3 of 5". A spend that fills a counting-up pool shows the pool's text (`resource.full`) once, on the status line.

**Allowance grouping.** An action or switch that spends an allowance pool is listed under that pool's name ("N of M left"), after the activation groups and apart from Reactions.

**Feature attacks and form-only actions (D43 slice 4).** "Attacks and actions" lists an attack a feature gives beside the weapons, under its own activation ("Actions" when it has none). Its summary reads "<name>: +N to hit, <damage> <type>" (the damage is left out when it could not be worked out), its details say "Melee attack" or "Ranged attack", the range, the pool it uses ("uses 1 Focus (spend it from the roll)") and "replaces one attack of the Attack action", and its trace lists the riders that applied and any that lost their stack group. "Roll <name> attack" and "Roll <name> damage (…)" roll it (the damage with the "Critical hit" box, which doubles the dice including a rider's). An action or an attack that is available only while a form is on is shown with its buttons disabled and the reason beside them ("Available in Kindled mode"); an attack that could not be worked out says why and is not rolled. See [play-mechanics.md](play-mechanics.md) "Slice 4" and accessibility checklist row 75.

**Action details and amounts (D43 slice 5).** An action's roll shows one detail line under it, such as "Save: DC 13 Dexterity · 100-ft line, 5 ft wide · Range: Self · Each creature in the line" (parts it does not declare are left out; a DC that cannot be worked out reads "Save: Dexterity (DC unavailable)"). An action that spends extra points for extra dice has a number box "Points to spend (<pool>)" that starts at its base cost; Roll always rolls with that amount, and an amount outside the allowed range disables Roll with a reason beside it. An action with no dice and a pool is a "Use <name> (<cost> <pool>)" button that spends its cost; it is disabled, with the reason as text beside it, when its form is off, the pool is short, the cost cannot be worked out ("Cost unavailable") or is 0 ("Costs nothing here"). The roll record's Spend button reads "Spend <amount> <pool> (<n> left)" and spends exactly the amount that was rolled. See [play-mechanics.md](play-mechanics.md) "Slice 5" and accessibility checklist rows 77 and 78.

## Rolls on the sheet (SPEC C-04)

- Every ability modifier, saving throw, skill and initiative field has a "Roll" button on the Stats tab (a d20 test through the `roll` command), and the summary has a "Roll <Ability> check (+N)" button per ability. The "d20 rolls" radio group, in the summary at the top of the sheet since ADR-014 ([sheet-layout.md](sheet-layout.md)), chooses normal, advantage or disadvantage. **Automatic roll modes (D43 slice 6):** when content gives a field advantage or disadvantage, its button names it ("Roll Dexterity saving throw (advantage: <source>)", or "(normal: advantage and disadvantage cancel)"), the service combines it with the radio choice (advantage and disadvantage cancel), the Last roll names the sources, and modes that apply only against a condition, or that the content marks as not automatic, are listed as notes in the Stats card and never change a roll. A fly speed shows on Stats ("Fly speed: 30 ft.") and in the summary's Speed ("30 ft., Fly 30 ft.") only when above 0. See [play-mechanics.md](play-mechanics.md) "Slice 6" and accessibility checklist row 79. The result of a summary roll reads "Strength check: 14 (1d20)", the same words as its button (2026-10-06).
- **Attacks and actions** (M2 item 2, [multiclass-and-attacks.md](multiclass-and-attacks.md)): equipped weapons' attacks (to hit, damage, traced), and feature rolls grouped by action, bonus action, reaction and other. Since Wave 3 (item 22, R157) a content v10 toggle with an `activation` is listed in its group here too (an auto toggle stays switchless inside it), while a toggle with none stays in "Active effects"; a resource with an `activation` is listed in the same-named group in "Resources" (left column), the rest as before, and nothing moves between columns. Below v10 the `activation` key does nothing. "Critical hit" doubles damage dice. Resources and spell slots show pips beside the text (decoration only; the text is the value).
- The **Last roll** region (in the summary, visible on every tab; `aria-live="polite"`) shows the total, formula, mode, every die (dropped and critical dice are marked), the modifiers and the provenance (content, source, page). Since ADR-015 the region also draws the dice (hidden from assistive tech; the text is the result): they show the service's values at once and tumble for 0.6 s, unless reduced motion is on or the setting is off. At most ten are drawn; the text lists every die.
- **Rolling never spends anything.** If the roll names a resource (`linkedResourceId`), the record offers a separate "Spend 1 …" button (since D43 slice 5, "Spend <amount> …" with the amount the record carries as `spend`), which is a confirmed `character.play`.
- **Death saving throws** (the panel appears at 0 hit points, or while saves are recorded): "Roll death saving throw" rolls a d20 (`roll` with `deathSave: true`), and "Record death saving throw (N)" records it. "d20 rolled at the table" + "Record this roll" records a physical roll. The heading reads "Death saving throws: 1 of 3 successes, 2 of 3 failures".
- **Concentration** (D19): the Spells tab offers "Concentrate on {spell}" for prepared concentration spells (disabled while concentrating on that spell). The Play tab then shows "Concentration: {spell}" with the Constitution save roll ("Roll Constitution saving throw", which changes nothing) and the two confirmed outcomes, "Kept concentration" and "End concentration". After damage the heading adds ", Constitution saving throw DC {n} pending". A long rest's preview lists the end of concentration (untick it to keep it); damage that drops hit points to 0, or setting hit points to 0, ends it at once. The stored spell name is at most 200 characters (`play.concentration-invalid`; also `maxLength` in the character schema); a longer content name is clipped to 200 when concentration starts, never refused.
- The hit points panel shows the hit dice left and an "Inspiration" / "Heroic Inspiration" checkbox, and the summary has the same checkbox and one-point hit-point buttons.

## Details, languages and tools (item 17, D36)

The Notes tab ends with a form named "Details" (after Session notes and Gap notes; no new tab), saved with the character in `details` (character schema v9). Never calculated.

- **Fields (R86):** Personality (alignment, personality traits, ideals, bonds, flaws), Appearance (age, height, weight, eyes, skin, hair), Background story (backstory, allies and organisations), and Languages and tools (two lists, "Languages" and "Tools and other", one entry per line; blank lines are ignored, entries are trimmed).
- **Limits:** each text at most 2,000 characters; each list at most 30 entries of at most 80 characters (the service refuses more with the `character.details-*` codes). The form checks first. A text over the limit, a list line over 80 characters (named by line number) or more than 30 entries is a linked error (`aria-invalid`, `aria-describedby`); nothing is cut or dropped. Under 200 characters left, a hint says how many remain.
- **Bloodied (D38):** the summary's Hit points box shows a "Bloodied" chip (text, not colour alone, no live announcement) while current hit points are at or below half the maximum rounded down (21 maximum: bloodied at 10, not at 11), with a maximum of at least 1; temporary hit points do not count, and 0 hit points is still bloodied. Both rules families alike. A content v10 toggle with `autoWhen: "bloodied"` is on exactly while the character is bloodied: Play lists it under "Active effects" as "On while bloodied (on now)" or "(off now)" with no switch, a long rest leaves it alone, and Undo of the damage that bloodied the character is the exact hit point step with no toggle action, because the toggle is computed and never stored. The maximum used is the one without auto toggles, so an auto toggle can never move the line it is judged by. Computed toggles are not exported: the sheet export leaves them out (it lists only toggles you switch), and the Foundry export and the print view carry no toggles. See [m3-effects.md](m3-effects.md).
- **Damage types (item 21, D19 amended, R169):** Play's Hit points panel has a "Damage type" select beside the amount (first "Untyped", then acid to thunder). Typed damage uses the sheet's defences (`sheet.damageDefences`: the character's own `damageDefences` plus content v10 damage grants, each entry `{ type, kind, sources }`, absent when none). Order: immunity gives 0; otherwise resistance halves (rounding down), then vulnerability doubles (both: 13 becomes 6 becomes 12); then temporary hit points absorb; then hit points. A kind counts once however many sources give it. Untyped damage ignores every defence. Damage that is 0 after defences changes nothing and asks for no concentration check; the concentration DC uses the amount after defences and before temporary hit points. The result line reads "13 slashing, halved: 6." (also "immune", "doubled", "halved, then doubled", "no defence", "13 untyped: 13."), with "Temporary hit points took N." when they absorbed some. It is plain text, not a live region. Massive damage is a **warning** (`play.massive-damage`, numbers only), never an automatic death: the damage left over once hit points reach 0 equals or exceeds the hit point maximum (at 0 hit points the whole amount counts as left over). A weapon's or custom attack's damage roll pre-fills the select with its damage type when that names one of the thirteen (any case, nothing else; otherwise the select goes back to Untyped); the player can change it. Undo's label is "damage 13 slashing (6 taken)" (untyped: "damage 12"), and its steps are unchanged: the exact `setHitPoints`, the temporary hit points step, and the concentration steps. Grants: `damageResistance`, `damageImmunity` and `damageVulnerability` (content v10) count when they are automatic and always on, honour `level` (the same level gate as other grants) and `onlyAs`, and compare their `damageType` in any case; a conditional or assisted one is listed as assisted and not applied. A damage grant in a revision below v10 is an unknown effect and does nothing. The Stats tab lists the sheet's defences with their sources and edits the character's own list (Damage type, Kind, Add; Remove per entry); each press saves through the sheet's save queue and focus moves to the section heading. A duplicate (same type and kind) is refused before it is sent. With damage responses, see D45 in [play-mechanics.md](play-mechanics.md) "Slice 7" for the order.
- **Save (R77):** "Save details" is `aria-disabled` (never natively disabled) with a linked reason ("Nothing has changed yet.", "Save is held until the fields marked above are fixed.", "Saving the details…"). A press while held does nothing, and after a save the button keeps focus. The status says "Details saved." Clearing every field saves no `details`, so a character with no other v9 data is written as schema 8 again.
- **Other saves keep them:** every sheet save (equipment, coins, your own items and attacks, details, session notes, prepared spells, overrides) goes through one queue in the sheet (R92, R132). A panel passes its change as an updater, which is applied to the latest saved character, and the saves run one after another. So details (and the other v9 fields a panel does not edit) survive a save from any other panel, and two panels saving close together both keep their change. Each panel still shows its own success or failure. A view shown by another route while saves are queued (a snapshot restore, an applied update) is picked up when the next queued save starts, if its `updatedAt` is newer than the last save's result, so a queued save does not rewrite it. **A stale save is refused (R137, R161, R182).** `character.save` is compare-and-set on the `updatedAt` the save carries: the page sends the character back as it last got it, and the service refuses with `character.stale` ("This character changed since you opened it. Your change wasn't saved; the current copy is shown.") when that is not the stored `updatedAt`, writing nothing. Every play, rest, restore, companion and charge command stamps `updatedAt`, so a sheet that missed one is refused instead of writing over it. The sheet shows the refusal in the usual alert, reads the current copy (`character.get`) and shows it, and leaves focus where it was; what was typed stays in its field to apply again. The queue passes each successful save's returned `updatedAt` (as the exact text it got) to the next queued save, so quick edits in a row never refuse each other. Play actions (including spending a charge), Undo and a rest finish wait in the same queue (R188): each starts after the entry before it and hands its own returned `updatedAt` to the next, so a tick right after one of them is not refused. A new character has no stored version and is not compared. The builder's level-up and choices saves are compare-and-set too: a refused save says in plain words to cancel and open the character again, and the save button stays aria-disabled with that reason (the draft names a version that is gone). Whichever way the sheet's copy turns stale, it adopts the copy it reads back whatever its timestamp text sorts like, so a clock stepped back never wedges later saves. Equip and prepare toggles take their new value from the latest saved list (two quick presses toggle twice), and an edit, equip or prepare for an entry that is no longer on the latest saved character is refused with its own message and saves nothing (G9, G10).
- **Stats** lists the languages and the tools read-only, with an "Edit in Notes → Details" button that opens Notes and focuses the Details heading. Nothing shows while both lists are empty.
- **Where they go:** a share package keeps the details (D36) and still drops session notes and gap notes; a personal backup keeps everything. The sheet JSON and Foundry exports carry no details (Q17). A snapshot keeps them, and its restore preview names the detail fields it would change (never their text). The print preview prints them only when "Include details" is ticked ([printable-backup.md](printable-backup.md)).

## Companions (item 23, D39, R174)

Play's second column ends with a "Companions" section: one card per companion (a region named by the companion's name) with its kind, Armor Class, speed, hit points, attack lines and note, and Edit and Remove buttons. It is a **player-owned card of free text**: TomeStack applies no rules to a companion, has no monster rules and no stat-block import, and a rest changes nothing about a companion (current and temporary hit points stay as they are; the player sets them).

- **The definition is character data** (`character.companions`, schema v9, up to 10): name, kind, Armor Class (0–50), hit point maximum (0–10,000), speed, note, and up to 5 attack lines, each a `CustomAttack` (integer `toHit`, dice `damage`, optional `damageType`, note; never a content formula). The section's form adds, edits and removes a companion and its lines through the sheet's save queue (`character.save`), with the Wave 2 bounds and `character.companion-*` codes; the damage dice are checked by the dice engine before saving, as for "Your own attacks". A companion travels in backups and shares.
- **Hit points are play state** (`play.companions[{ id, current, temporary }]`), written **only** by `character.play`, never by `character.save` (C-05): `companionDamage` (the amount is untyped: temporary hit points absorb first, then current, at least 0; no damage type, defence, concentration, Bloodied, death save or massive-damage warning), `companionHeal` (up to the maximum; temporary untouched) and `companionSetHitPoints` (`amount` is the exact current, 0 to the maximum; `temporary` is the exact temporary hit points, 0–10,000, and is left as it is when not sent) and `companionSetTemporaryHitPoints` (`amount` is the temporary hit points, 0–10,000; the stored current is kept, so the "Set temporary hit points" button cannot undo a damage that landed first). All take `companionId`. An unknown or missing companion is `play.companion-unknown`; a current above the maximum is `play.companion-hit-points-above-maximum`; messages carry no names. Current at the maximum is stored as no value, and an entry with no current and no temporary hit points is not stored. A save that removes a companion drops its play entry.
- **Buttons** follow the character's hit point controls: "Amount", "Take damage", "Heal", "Set hit points" (the amount is the new current) and "Set temporary hit points". An invalid press is held (`aria-disabled`, a linked reason, "Enter an amount first." while the amount is blank) and does nothing; focus stays on the pressed button. "Set temporary hit points" sends `companionSetTemporaryHitPoints`.
- **Undo (D23):** each companion action is undone by an exact `companionSetHitPoints` that restores both current and temporary hit points (a companion with no recorded hit points reads as at its maximum with none temporary). A change that changed nothing has no Undo. After Undo, focus moves to the companion's heading.
- **Attack lines roll** through `roll` with `companionAttack: { companionId, attackId }`: the attack roll is a d20 plus the typed to-hit (with the d20 mode choice), `damage: true` rolls the damage dice (`critical` doubles them), exactly as for "Your own attacks". The record reads "<companion>: <attack> attack" / "damage (<type>)" with `rollId` `companion.attack` / `companion.damage`. Refusals: `roll.companion-unknown`, `roll.companion-attack-unknown`, `roll.companion-attack-no-damage`, and `roll.ambiguous` with another target. Rolling changes nothing.

## Spells tab: filters (P09, D70)

- Beside the name search (D30), each caster has a **Filters** button (`aria-expanded`) that opens a "Filter {caster} spells" group: level (0 is "Cantrip", up to 9), school (the schools that caster's spells have, compared without regard to case), casting time (Action, Bonus action, Reaction, "Longer or not stated"), Concentration and Ritual (Any, Yes, No), and "Clear filters". An empty group means any; the groups combine with AND, and the name search still applies.
- A casting time is read from its leading words, with or without a leading "1 ", in either SRD wording ("1 bonus action", "Bonus Action"). "Action or Ritual" and "1 action or 8 hours" count as an action; any other time ("1 minute", "10 minutes"), and a spell with no casting time, as "Longer or not stated". A spell with no school stays in the list with no school ticked and is hidden as soon as a school is ticked.
- The count ("N of M spells shown") is the search box's existing polite status, now also shown while any filter is set. It changes only when the count changes. When the filters hide every spell the list says "No spells match these filters. Clear filters to see all M."
- The choices are kept per caster while the sheet is open (a second caster has its own) and are not saved. The builder's spell pickers are unchanged. The logic is `filterSpells` and `castingBucket` in `src/Ui/src/spellSearch.ts`.

## What needs you by hand (P18, D69)

The end of the Features tab has "TomeStack won't do these for you" (`ByHandPanel.tsx`), with the line "TomeStack never acts on its own; these need you." Each row names the feature and its source page. Groups with nothing in them are not shown, and a sheet with nothing to list says "Everything on this sheet is calculated."

- **Spend by hand:** a feature's roll that names a resource (read from the sheet, the same test the mechanics report uses for limited-use actions).
- **Reference only:** effects TomeStack knows but does not apply. A feature that is only text is never listed (an SRD sheet would list hundreds).
- **Partly automatic:** effects that need the player, including one that has a problem (a formula that fails).
- **Not understood:** effects of a type this build does not know. A row here is not repeated in another group, and a roll listed under Spend by hand is left out of Reference only and Partly automatic (matched on the feature revision, the effect id and the effect type).

It is UI only: it reads the existing `character.mechanics` command (`client.characterMechanics`) for the sources the sheet's features come from. It asks only while the Features tab is open and again when the sheet is recalculated; a reply for an older sheet or another character is ignored. A sheet with no sources makes no call. If the read fails the panel shows "Couldn't list what needs you by hand." and nothing else.

## Not in this slice

Conditions that change calculations, and damage at 0 hit points adding a death save failure by itself (the player presses "Add a failure").
